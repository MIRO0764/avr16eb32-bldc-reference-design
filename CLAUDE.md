## What this is

Firmware for Microchip's Intelligent BLDC Reference Design: an **AVR16EB32** MCU driving a BLDC motor (ACT57BLF02, 26–48 V) through an **ATA6847** gate-driver ASSP. The AVR generates PWM via the TCE + WEX peripherals; the ATA6847 is configured over SPI0. Built on the MCC-generated **AVR MCU Motor Control Library** (`mclib`).

Two independent MPLAB X projects, nearly identical trees:

| Project | Control | `mc_config.h` | Commutation feedback |
|---|---|---|---|
| `AVREBBLDC_REF_SINDRIVE.X` | Sinusoidal, sensored | `MC_SENSORED_MODE`, `MC_CONTINUOUS_MODE`, `MC_WAVE_SADDLE` | Hall sensors (`MC_Hall_IntGet`) — requires board HW mod (cut BEMF sense jumpers, wire Halls) |
| `AVREBBLDC_REF_TRAPDRIVE.X` | Trapezoidal, sensorless | `MC_SENSORLESS_MODE`, `MC_STEPPED_MODE` | Back-EMF (`MC_Bemf_IntGet`) |

A change meant for both drives must be applied to both projects manually — there is no shared source.

## Build

Toolchain: XC8 v3.10 (`C:/Program Files/Microchip/xc8/v3.10`), AVR-Ex_DFP 2.11.221, CMake + Ninja. Projects are managed by the MPLAB VS Code extension (`.vscode/*.mplab.json` is the source of truth for compiler options: `-O1`, short enums, gc of unused functions/data). The `cmake/<project>/default/` directory and `.generated/` files are regenerated by the extension from the `.mplab.json` — don't hand-edit them.

CLI build (from repo root, once the extension has generated `cmake/`):

```sh
cmake --preset AVREBBLDC_REF_TRAPDRIVE_default_conf -S cmake/AVREBBLDC_REF_TRAPDRIVE/default
cmake --build _build/AVREBBLDC_REF_TRAPDRIVE/default
```

(Substitute `SINDRIVE` for the other project.) Output: `out/<project>/default.{elf,hex,lss}`. Ninja lives at `~/.mplab/app-finder/apps/ninja/`. Programming is done with PICkit 5 over UPDI (PF7). There are no unit tests; verification is on hardware (UART output viewed in MPLAB Data Visualizer).

## Architecture

- `main.c` — the only hand-written application file. `SYSTEM_Initialize()` → `MC_Example_Initialize()` → ATA6847 bring-up over SPI (`ATA_Setup`: watchdog trigger sequence, GDU/current-sense/current-limit registers, device op mode), waits for `NIRQ` low, then sets `REG_GDU_OP=0x07` to enable the gate driver, then loops `MC_Example_Run()`. ATA SPI frame: `reg<<1` for write, `(reg<<1)|1` for read; CS is a GPIO (`ATA_CS_*`) toggled around each transfer.
- `mcc_generated_files/mclib/` — motor control library. `mc_config.h` holds all motor/board parameters (control/drive mode, wave profile, motor R/L/poles, current gain, ADC reference, speed regulator limits). `motor_control.c` selects `MC_SENSOR_GET`/`MC_SENSOR_SET` by control mode; the state machine is built from `mc_sm.h` macros (`SMTD_STATES_*`).
- `mcc_generated_files/mclib/example/` — demo app (button start/stop, potentiometer speed, LEDs, periodic UART print, fault reporting).
- Other `mcc_generated_files/*` — MCC peripheral drivers (AC0/AC1, SPI0, UART, VREF, delay timer, pins, clock — 20 MHz, prescaler disabled).

### MCC-generated files that were hand-modified (TRAPDRIVE)

Regenerating with MCC (`*.mc3` files) **will overwrite** these, so re-apply the changes afterwards (README steps 10–13 document them):

- `mclib/mc_pins.h` — `CRT_REF_ADC_PIN` changed to `ADC_MUXNEG_GND_gc`.
- `mclib/mc_sensing.h` / `src/mc_sensing.c` — added `MC_Bemf_Set`, `MC_Sense_Set`, `MC_Sense_Get`; BEMF sensing reworked for this board. These change only the commutation feedback source, not the library state machine.
- `main.c` — ATA6847 programming sequence.

SINDRIVE only modifies `main.c` and `mc_config.h` choices; `mc_pins`/`mc_sensing` stay as generated.

### Known inconsistencies

- SINDRIVE `main.c` defines `REG_WDCFG1` as `0x20` (same as `REG_WDTMR_TRIG`); TRAPDRIVE writes the WD config to `0x21`.
- TRAPDRIVE `mc_sensing.h` declares `MC_sense_Set` while `mc_sensing.c` defines `MC_Sense_Set`.

## Hardware notes

- PCB silkscreen is swapped: the button labeled **Reset** is a GPIO (user button), the one labeled **User SW** is the MCU reset.
- Pin map is in `README.md` (PA0–PA5 = phase PWM H/L, PD4–PD7 = SPI to ATA6847, PC1/PC2 = UART, PD0 = fault, PC3 = ATA IRQ).
